# Rice Patrol 🍚🐋

[English](README.md)

Rice Patrol 是给 DeepSeek Harness（DSH）用的插件。它盯着模型输出的思考文本：如果连续出现大量重复、越来越短的句子，就按你选的模式记录、停止，或者尝试接着做。我们把这种重复叫作“唱歌”。

只要模型通过 DSH 的通用接口提供思考文本，插件就可以观察；不同模型和服务商的实际效果仍需分别验证。

## 安装

目前按 DSH `0.1.6-alpha.2` 开发和测试。在终端运行：

```sh
dsh plugin --profile web add github:LeeLizuoLiu/rice-patrol#v0.2.1
```

然后重启 DSH Web，打开 **Plugins → rice-patrol**，确认插件和里面的组件都显示为已启用。**只安装包或只打开外层开关，都不足以证明组件正在运行。**

## 三种模式

| 模式 | 检测到持续重复后会怎样 |
| --- | --- |
| **Stop（默认）** | 停止当前任务，不自动继续。 |
| **Observe** | 只记录，不打断任务。 |
| **Recover** | 先停止，再整理已有记录，尝试让一个新 Agent 接着做未完成的部分。 |

可以在插件的网页设置卡里选择模式，**保存后需要重启 DSH Web**；正在运行的任务不会中途换模式。如果设置卡没有出现，或组件仍显示 Off，请先不要认为保护已生效。

Recover 会先停止“唱歌”的那一轮，整理明确的用户要求和已经结束的工具记录，做一次有上限的 compact，再让一个新 Agent 接着做。交接里只保留最近 128 条操作；第 129 条进来时，最老的一条移出。较早操作的去重指纹仍单独保存，防止恢复时原样重复执行。新 Agent 使用 DSH 原本允许的工具和权限。

恢复有上限：compact 最多 45 秒；新 Agent 最多运行 5 分钟、调用模型 16 次、调用工具 128 次。如果后台任务还在运行、结果未确认，或工具记录对不上，插件会停下来提示你。历史工具报错会如实保留为“报错”，不会被说成已经成功。自动恢复只尝试一次，不会反复启动新 Agent。

恢复结束或需要你处理时，状态提醒会显示“关闭提醒”。点击后只隐藏这次提醒，保留状态记录；新的恢复事件仍会显示。正在运行的恢复仍使用“停止恢复”按钮。

## 它能做什么，不能做什么

- 它检测的是 DSH 能看到的思考文本中的短句重复。看不到的思考内容、普通回答里的重复，以及单纯的 **Output token limit reached**，目前不在检测范围内。
- Stop 和 Recover 会在确认重复后尝试停止。曾有正常工具交接在确认后约 2 秒才出现，所以它可能过早打断正常任务。希望先看记录时，请选 Observe。
- Recover 会额外调用模型；停止本地输出也不代表服务商已经停止计费。
- 插件不会给每个普通请求额外加一个 180 秒期限。

v0.2.1 通过了 51 项本地测试，包括“关闭提醒”的界面、状态保存和假上游接口测试；没有新增真实模型调用。此前还对一段已保存的长会话做过只读交接检查。较早版本曾通过两个合成服务商的隔离 Web 测试，**v0.2.1 还没有重新通过完整 Web 流程**。真实服务中的误判率和跨服务商效果仍需继续验证。
