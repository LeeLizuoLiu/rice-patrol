# Rice Patrol 🍚🐋

[English](README.md)

Rice Patrol 是 DeepSeek Harness（DSH）的“唱歌”拦截插件。“唱歌”指模型在思考时反复输出短句，迟迟不推进任务。插件通过 DSH 的通用接口读取**可见的思考文本**；它不依赖特定服务商。

## 怎么判断“唱歌”？

插件按换行把思考文本分成非空行（去掉每行首尾空格），持续查看最近 **50 行**。当这 50 行的长度中位数不超过 **20 个字符**，且至少 **70% 的行**能在同一窗口找到一行完全相同的内容时，记一次**预警**。再输出至少 50 行后，如果新窗口也符合条件，才算**确认**。

它不寻找 `Let me` 等触发词，也不要求每一行都比上一行短。只到预警时不会拦截。每次模型请求单独判断；普通回答中的重复和 DSH 没有提供的思考内容看不到。

## 确认之后怎么办？

在 **Plugins → rice-patrol** 中选择：

| 模式 | 行为 |
| --- | --- |
| **Stop（默认）** | 停止当前任务，等你决定下一步。 |
| **Observe** | 只记录，不停止任务。 |
| **Recover** | 停止当前请求，把中断的思考从模型可见历史中移走，再让原来的主 Agent 接着做。 |

Recover **每个用户回合最多自动尝试一次**。同一 Session 后续收到新的用户消息，如果再次唱歌，会重新尝试恢复；主 Agent 在同一回合再次唱歌则停止，不会无限重启。若宿主报告仍有后台任务，它会停下来提示你。恢复完成或受阻后，可点“关闭提醒”；记录仍会保留。插件按钮和说明跟随 DSH 的界面语言（中文或英文）；DSH 没有手动指定语言时，会参考浏览器的系统语言偏好。模式保存后需重启 DSH Web 才生效，运行中的任务不会中途换模式。

交接顺序是：等待宿主停止当前生成并确认没有活动的宿主后台任务，再把本次中断的思考消息从模型可见历史中替换掉。原始记录仍留在 DSH 日志中。主 Agent 沿用之前的对话接着工作；Rice Patrol 不额外调用模型做摘要，也不逐条解析其他插件的工具历史或拦截后续工具。若以后上下文接近上限，DSH 原有的自动 Compact 仍可运行。已经完成的文件修改不会被删除。

## 安装

恢复开始前已经排队的消息会保留原文和顺序。恢复期间新发送的指令仍会中断本次恢复；编辑排队消息会阻止旧交接继续。界面区分“正在等待接续响应”和“主 Agent 已接续”；后者只表示原 Agent 已返回新一轮输出，不表示用户任务已经完成。

`resumeTimeoutMs` 限制交接提交及其后等待首次接续响应的各阶段（默认各 5 分钟），不限制主 Agent 后续任务总时长或请求次数。无法核对中断消息或宿主活动任务时会暂停。详情见 [历史恢复记录](docs/SINGLE_AGENT_RECOVERY.md)。

面向 DSH `0.1.6-alpha.2` 构建。在终端运行：

```sh
dsh plugin --profile web add github:LeeLizuoLiu/rice-patrol#v0.2.9
```

重启 DSH Web，在 **Plugins** 页面启用 rice-patrol **及其组件**，再到插件设置里选择模式。只安装插件、没有启用组件时，拦截不会工作。

## 当前限制与后续计划

- **50 行、两次命中**是当前固定规则；网页里还不能调整。后续可考虑让用户自行选择每个窗口的行数和确认所需的窗口数。
- 检测可能误判：曾有正常工具交接在确认后约 2 秒才出现。Stop 和 Recover 会立即尝试停止；想先了解自己的工作流，可选 Observe。
- Recover 不再额外调用模型做摘要。主 Agent 接续后按 DSH 正常任务运行；Rice Patrol 不给它设置模型请求次数或工具调用次数上限。停止本地输出不保证服务商停止计费。
- 不同模型和服务商的效果仍需分别验证。单纯的 **Output token limit reached** 不是本插件的检测对象。
- Recover 不提供工具操作的精确去重；接续时主 Agent 应先检查工作区状态。宿主无法确认活动任务已结束时会暂停。已暂停的旧恢复不会自动重试。

v0.2.5 加入 compact 达到输出上限时的有界交接，并显示更具体的暂停原因。已只读检查这次 WeakDALearning 故障，但旧日志没有保存 compact 的准确结束类型，因此这里只修复一个有依据的可能原因，不能宣称已证实。60 项本地测试通过，其中包含合成 AgentLoop 的降级交接；本次没有调用真实模型。以前已暂停的恢复不会自动重试。测试范围和细节见 [恢复验证记录](docs/RECOVERY_0_2_VALIDATION.md) 与 [早期 Web 验证记录](docs/VALIDATION.md)。项目使用 MIT 许可。

v0.2.6 将恢复机会绑定到新的用户消息。同一 Session 后续再次唱歌，会自动尝试新的交接；旧版本留下的“整个 Session 已用过恢复”的记录不会挡住新消息。每条用户消息仍只尝试一次，恢复中的新 Agent 如果再次唱歌会停止。65 项本地测试通过，包含假上游的多轮恢复；尚未验证真实服务。

v0.2.7 改为将摘要写回原会话，让原来的主 Agent 接着做。旧的 16 次请求上限不再适用。本地假服务测试已验证这一流程和超过 16 次的后续请求；真实服务效果仍需在正常使用中观察。

v0.2.8 沿用 DSH 的正常历史，只从模型可见历史中替换本次中断的思考消息，不再额外调用模型做摘要。它也会核对已结束的 `/permission`、`/plan`，并在恢复期间暂存子 Agent 的回报。本地包已安装；按你的要求，这条直接接续流程发布前没有运行测试。旧流程记录见 [历史验证笔记](docs/SINGLE_AGENT_RECOVERY.md)。

v0.2.9 去掉 Recover 对历史工具结果的逐条解析和后续工具调用拦截。按用户要求，本次修改未运行测试；安装后仍需重启 DSH Web 才会生效。
